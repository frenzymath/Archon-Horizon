# Delegate Or Wait

Delegate when a narrower, independently checkable task helps finish the assigned
result. Give it the objective, exact inputs, allowed files, acceptance condition
and integration owner. Check existing ownership first. Do not recreate the same
whole mission under a new name, or split shared interfaces into competing writers.
The mission and assignment instructions are authoritative; native goals are
optional mirrors and need no parallel reporting workflow.

## Choose The Lifetime

| Need | Mechanism |
| --- | --- |
| Short investigation or independent edit collected in this execution | Native child |
| Work that must survive this execution or use another primary slot | Durable assignment |
| Existing owner's concrete task resumes after an external result | Event-conditioned checkpoint |
| A formal independent PR assessment | Prepared reviewer in its configured invocation mode |

A native child receives only the relevant specialty guidance and task evidence.
Use the provider's actual spawn tool and returned ID; a descriptor name is not
an agent type or permission. Collect the result before ending its parent, and
inspect the evidence before integration. Read `$HORIZON_SKILLS_DIR/SUBAGENTS.md`
only when choosing a specialty would help. Unsupported native delegation calls
are not a reason to retry the same launch repeatedly.

A durable child needs an appropriately scoped mission and assignment. Reuse a
suitable existing mission; create a narrower child only when it represents
distinct responsibility. Mission creation requires acceptance criteria, a
delegation note, the current parent revision and a contained scope. Assignment
creation supplies the run, mission, role, concrete instructions and any real
dependency. See [queue requests](references/queue.md) for payloads and conditions.
Creating work does not complete it: delegate the corresponding obligation only
after the child exists, and keep integration with an identified owner.

Workers can create worker tasks inside their permitted subtree. Maintainer work
requires maintainer authority. A child cannot close siblings or ancestors;
root closure stays with a root-authorized maintainer. Instructions do not widen
these permissions. Child budgets are adjustable mission contracts, not worker
slot counts. On exhaustion, close genuinely fulfilled children or make a
revision-checked budget change for real unfinished work.

## Preserve The Repair Loop

When a reviewer requests changes, give the existing author the exact findings
and changed-head scope when that owner is still active or checkpointed. Resume
the next action in its retained context instead of repeating source discovery.
Ordinary agents cannot resume a completed assignment: that requires an operator,
and a reassigned workspace can prevent it. If continuation is unavailable, create
one narrow repair task linked to the existing PR, findings and evidence.

For an already arranged external review or child result, the current integration
owner may request `checkpoint_assignment` with a concrete event condition and
then end its provider turn. The scheduler releases the slot and retains its
context. Include failed/cancelled outcomes so it can recover a broken handoff.
Do not checkpoint on your own result, on a producer needing your retained
workspace, or on speculative future feedback. A checkpoint is a wait with real
unfinished work, not an approval or a completed obligation.

For prepared review, follow [horizon-review](../../review/horizon-review/SKILL.md).
The descriptor chooses `assignment` or `subrequest`; neither is a universal
default or a fallback for the other. Durable reviewers need no live parent.
Reuse the existing integration owner through a supported checkpoint when
possible; otherwise arrange one narrower owner conditioned on their terminal
results. Native reviewers must be collected by their live parent. Direct advice
from an ordinary child does not satisfy an independent review policy.

## Planning And Ownership

A planning owner checks current assignments and compatible capacity before
changing the frontier. Queue enough independent work to make progress; ordinary
authors need not manage the fleet. Avoid another planner, maintainer or audit
when an existing owner already covers the same result. If no work is ready,
record the concrete producer and unlock condition, then finish or checkpoint.

Change an existing recurrence through `defer_automation`; editing an occurrence
does not change its rule. Inspect actual pending conditions after changes. Every
wait needs an independent producer, and spare capacity cannot override a real
external dependency. Use [queue requests](references/queue.md) only when doing
this scheduling work.

A handoff needs the artifact or finding, checks already performed, remaining
question and next owner. Link previous evidence rather than copying transcripts.
After a child failure, preserve useful work and correct its specific cause
before retrying. Use [completion](../horizon-report/SKILL.md) for the current
ledger and mission requirements.
