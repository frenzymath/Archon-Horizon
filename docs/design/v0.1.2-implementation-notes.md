## 0. The run, end to end (as of now)

```
horizon run <target> [--rounds N] [--supervisor] [--resume ID]
└─ commands/run.py RunCommand.run()
   ├─ starts the dashboard thread (unless --no-dashboard)
   ├─ interactive? → _run_interactive() → horizon_seed_prompt (skill-first seed)
   ├─ --resume?    → _resume_run() → orch.run(resume=True)
   └─ else         → _build_run() → one RunRecord → orch.run()
                     └─ _exit_if_paused(): exit code 3 if the run paused

orchestration/orchestrator.py Orchestrator._run_locked()
   ├─ clears runs/<id>/paused.json; resets run-budget accumulators
   ├─ per round: queue focus → refresh parser DAGs → scheduler.select_tasks
   │  └─ per task: _horizon_step()
   │     ├─ meta.json written (status: running, harness/model/effort)
   │     ├─ watcher thread: cancels on external `task set <terminal>` OR
   │     │  session_tokens_out budget crossed (reads live usage.json, 2s poll)
   │     ├─ HarnessHorizonAgent.run_task()
   │     │  ├─ prompt = agents/prompts.horizon_task_prompt (directive + skill)
   │     │  └─ CommandHarness.run(): subprocess → stream parse → transcript.jsonl
   │     │     ├─ _UsageFile: live usage.json next to the transcript
   │     │     ├─ retry transient failures (backoff, honors "retry after Xs")
   │     │     └─ classify failure: typed ERROR events first, stderr regex second
   │     ├─ agent-owned terminal status (task set done/blocked/failed) or → QUEUED
   │     └─ integrate_workspace_session → one ledger commit
   ├─ after each task: run budget check (tokens_out / cost)
   ├─ on fatal (auth/usage-limit/aborted-early/session_budget/budget):
   │  run.stopped + _write_pause_marker → paused.json
   └─ publish boundary: workspace_dags_rich → hgraph sync → cached DAG JSON
```

## 1. Phase A — what was deleted and why it was safe

Everything removed had **zero production callers** (verified by grep before each
deletion; the exploration reports are summarized in the companion doc §2):

- `config/schema.py`: `roles`, `start_with`, `end_with`, `ground_subagents`,
  `subagent_harness`, `ReferenceTranscriptionConfig` (+ its two resolver
  properties), `scheduler.unknown_write_set_policy`. `WorkspaceConfig.from_raw`
  simply no longer reads those keys — an old `config.yaml` still loads
  (pinned by `tests/test_config_loader.py::test_unknown_workspace_keys_are_ignored`).
- `vcs/integration.py`: the cross-process commit queue
  (`_workspace_commit_queue`, stale-lock reclaim, pid/host checks). Runs are
  sequential with a single committer; what remains is one in-process
  `threading.Lock` ordering the dashboard thread vs. the run loop.
- `vcs/git.py`: `ProjectGit`/`project_git_for`/`collect_revisions` (the
  pre-single-ledger model), `session_commits` (tuple variant), git-notes
  helpers. `session_commits_detailed` is the one query the server uses.
- `leandag/`: `exporters.py` (1,355 lines, mostly an inlined JS app),
  `queries.py`, `reporter.py`. Only scanner + parser + DAG build remain.
- `inboxes/memory.py` (`InMemoryInboxProvider`) — unused even by tests.
- Agent-facing truth fixes: `skills/subagents`, `skills/horizon-inbox`,
  `skills/task-status`, `skills/mathlib-conventions`, `skills/references`,
  `subagents/base.py` prompt, and the `blueprint`/`work-reviewer`/
  `reference-retriever`/`page-transcriber` descriptors no longer describe an
  active Ground agent or the removed `references.transcription` config.

**⚠ decision:** `cfg.ground_harness` (the `workspace.ground_agent.harness` key)
was *kept* — `horizon discuss`, the post-init advisor, and `horizon subagent`
still use it as their harness pointer. Renaming it (e.g. `aux_harness`) is a
config-breaking change I did not take. (`config/schema.py`, field comment.)

## 2. Phase B — dashboard hot path (`server/service.py`, `server/app.py`)

Four independent mechanisms; each can be reverted alone.

### 2.1 Session-state cache
`WorkspaceService._session_state` is now a cache wrapper around
`_compute_session_state`. Key: `str(session.path)`; validity signature:
`[transcript mtime_ns, size, meta.json mtime_ns, size]` (`_session_sig`).
- Cached node **excludes** `children` — rebuilt from disk every poll so a live
  session's subagents appear as they materialize; `run`/`parent` are stamped by
  the wrapper.
- The wrapper returns `dict(cached_node)` (shallow copy) because `_run_state`
  mutates top-level keys (`status` running→interrupted flips,
  `workspace_commit` annotation). Nested values (`meta`, `usage`) are never
  mutated downstream — if you ever mutate them in `_run_state`, deep-copy here.
- **Persistence:** `.archon-horizon/cache/session-states.json`
  (`{"version": 1, "sessions": {path: {sig, node}}}`), saved at most every 30 s
  when dirty (`_save_session_cache`, atomic tmp+`os.replace`), loaded in
  `__init__`. Version bump invalidates wholesale. The `cache/` dir is excluded
  from the ledger (`git.py _WORKSPACE_EXCLUDES`), from init's `.gitignore`, and
  from the change stamp (below) — a cache write can never dirty the ETag.
- Mid-append safety: after a cache miss computes, the signature is re-taken;
  if it changed during the read, the result is served but **not** cached.

### 2.2 Subagent materialization off the read path
`materialize_subagent_sessions` (idempotent, but it re-reads the parent
transcript and rewrites `subagents/*` files) now runs:
- on the write path: harness end (`command.py _attempt`, unchanged) and
  interactive capture end (`interactive.py run_interactive_captured`, added);
- on the read path **only inside `_compute_session_state`** — i.e. once per
  session per server lifetime (cache miss), covering live sessions mid-stream
  and old sessions that crashed before materialization.
`transcripts()`/`_collect_session` no longer materialize at all.

### 2.3 ETag short-circuit before compute
`WorkspaceService.state_stamp()`: one `os.walk` over `config.yaml` + the state
dir, **skipping** `vcs/`, `locks/`, `cache/`, `search/`
(`_STAMP_SKIP_DIRS`), producing `"{max_mtime_ns}-{file_count}-{total_size}"`.
`app.py do_GET` special-cases `/api/state`: ETag = `W/"<stamp>"`, and on an
`If-None-Match` hit answers **304 without calling `state()`** (~85 ms vs ~12 s
on the reference workspace). Every other endpoint keeps the body-hash ETag.
- **⚠ decision / known imprecision:** anything `state()` reads that is *outside*
  the stamped tree will not invalidate the ETag until something else changes.
  Today that is only `_search_libraries()` (config + `.lake` package names) —
  effectively static. If `state()` ever grows a new input, add it to the stamp.

### 2.4 Incremental collections
- `_events_all()`: `events.jsonl` is append-only, so the parsed list plus a
  byte offset is kept; each poll parses only the appended tail (partial last
  line is deferred to the next poll via `rfind(b"\n")`; truncation triggers a
  full re-read). `state()` parses once and hands the list to `_runs_state`.
- `_light_dags_cached()` / `_cached_by_stamp(...)`: the lightened blueprint
  DAGs and the tasks / roadmap / local-inbox / github-inbox payloads are cached
  against a stat-walk stamp of their directories — hundreds of per-item YAML
  loads become one walk when unchanged.

## 3. Phase C — the skill-first prompt

### 3.1 What an automated session receives now
`agents/prompts.py` is ~60 lines: `horizon_task_prompt(context)` renders

1. `You are in an **Archon Horizon** workspace at <root>.`
2. `Load the **horizon** skill FIRST … read .claude/skills/horizon/SKILL.md
   directly` (the engine-agnostic path is spelled out for Codex);
3. `# Task` — id, title, project(s)+paths, `roadmap=`/`inbox=` refs, body;
4. one-shot framing + "finish with the report the skill specifies".

Nothing else is pushed. Deleted: `compose_horizon_prompt` and every section
renderer, `agents/prompt_templates/`, `install_prompts`, the
`<state_dir>/prompts/` override mechanism (init `--update` warns once that old
override files are inert).

### 3.2 Where the load-bearing prose went
- Report shape (`## Progress` / `## Why I stopped`, bullet style, "take the
  next action before stopping") → `skills/horizon/SKILL.md` §Final report.
- Task-status ownership (`--status done` only when FULLY complete) → horizon
  skill §Pick the highest-value work + the existing `task-status` skill.
- Delegated-model economy (cheap tier for mechanical work, check usage before
  fan-out) → `skills/subagents/SKILL.md` §Model tier.
- Pinned by `tests/test_agent_contract.py::test_horizon_skill_carries_the_load_bearing_conventions`.

### 3.3 Engine-native orientation
`commands/init.py _install_orientation_files`: writes `CLAUDE.md` and
`AGENTS.md` at the workspace root (identical 6-line body → read the horizon
skill; one-shot discipline). Uses the existing `_sync_managed_file`
keep-vs-overwrite policy: a user-edited file is never clobbered silently.

### 3.4 Interactive = the seed, always
`horizon_seed_prompt(root, focus, resuming=…)` is now the only interactive
seed; `interactive_role_prompt`/`_ROLE_BRIEF` are deleted; `--bare` is a
shorthand for `--backend interactive`. `discuss` keeps its own prompt.

**⚠ decision:** the plan said "A/B against the heavyweight flow on one real
project before deleting". You said "do everything planned", so the composed
prompt is deleted outright — git history (`ff09840^`) has it if an A/B shows a
regression. Watch the first few OpenGA runs for orientation quality.

**⚠ behavior change:** inbox items / protections / memory are no longer
*pushed* into the prompt. An agent sees them only by running
`horizon inbox list` (the skill instructs this, and protections still hard-block
frozen tasks via the scheduler). If a session ignores the skill, it can miss a
protection that the old prompt would have shown. The mitigations are the
orientation files + the skill; if that proves too weak, re-adding a one-line
"you have N open inbox items addressed to you" to the directive is cheap.

## 4. Phase D — one launch path, identity-only context

- `commands/run.py _build_run(orch, default_rounds)`: role target ⇒ 1 round;
  `--supervisor` with no targets ⇒ empty focus (all queued work) at configured
  rounds; plain targets ⇒ resolved focus at configured rounds; `--run`/
  `--round` append into an existing run. `--supervisor` is now *only* a
  permission to run with no explicit target — it changes nothing else.
- `HorizonContext` = workspace, run, task, log_dir, resume_session_id, cancel.
  The per-session loads of roadmap slice / accepted inbox / memory are gone
  from the orchestrator (they existed only to feed the deleted prompt).
- `core/permissions.py` deleted: write-domain "violations" were advisory events
  nobody consumed. Real constraints that remain: freeze rules
  (`core/freeze.py`, still block task dispatch) and inbox `protection` items.
- **⚠ decision (deviation from the plan):** the task-terminal watcher thread
  stays. It is the only external kill switch for a live engine
  (`horizon task set <id> --status done` from another terminal cancels the
  session), and Phase E reuses its cancel path for session budgets. Cost
  reduced by polling at 2 s instead of 0.5 s (`_TASK_CANCEL_POLL_S`).

## 5. Phase E — usage, budgets, limits

### 5.1 Live usage file (`harnesses/command.py _UsageFile`)
Every parsed stream event passes through `_UsageFile.add`; USAGE events
accumulate into `<session_dir>/usage.json`:

```json
{"tokens_in": 0, "tokens_out": 0, "cached_tokens_in": 0,
 "reasoning_tokens_out": 0, "cost_usd": null, "usage_events": 0,
 "started_at": 1752…, "updated_at": 1752…}
```

Atomic rewrite (tmp+replace), rate-limited to one write per 2 s, forced flush
after streaming ends. Telemetry failures never raise. Both engines feed it:
Claude's per-message `usage` and Codex's `turn.completed` are already parsed
into USAGE events (`transcript/parsers.py`).

### 5.2 `horizon usage` (`commands/usage.py`)
Resolution: `--run` > `$ARCHON_HORIZON_RUN` > latest run dir;
`$ARCHON_HORIZON_SESSION` names "me". Session usage = live `usage.json`, else
the finalized `meta.json.usage`. Run totals = sum over session dirs. Also
reports: configured budgets + headroom, `failure_reason`s from this run's
session metas (rate/usage-limit signals), and `paused.json` if present.
`--json` for agents (documented in the horizon + subagents skills).

### 5.3 Budgets (`config/schema.py BudgetConfig`, `workspace.budget`)
- `session_tokens_out`: checked by the watcher thread against the live
  `usage.json`; crossing it cancels the session and stamps
  `failure_reason="session_budget"` (fatal ⇒ the run stops rather than
  respawning a session that would burn the same).
- `run_tokens_out` / `run_cost_usd`: accumulated in `_run_locked` from each
  result's usage metadata; checked **between** sessions ⇒ `reason="budget"`.
- All unset ⇒ `budget=None` on the orchestrator (loader passes it only
  `if cfg.budget.configured`). Cost is the engine-reported/estimated
  `cost_usd` — with no pricing configured it can be `None`, and then only the
  token ceiling can trigger.

### 5.4 Failure classification and pausing
- `parse_claude_line`: a `result` line with `is_error`/`subtype:"error…"` now
  emits a typed `ERROR` event (subtype preserved). `_attempt` classifies over
  `error-event text + stderr + final text` (order matters: typed first).
- `_advertised_retry_s`: regex over "retry after Xs / try again in N seconds /
  retry-after: N", capped at 15 min; used to *stretch* (never shorten) the
  exponential backoff, and recorded as `retry_after_s` on the result/end event.
- `_write_pause_marker` (orchestrator): on any fatal stop writes
  `runs/<id>/paused.json` `{run_id, reason, at, focus_tasks, focus_projects,
  resume, retry_after_s?}` and sets `orch.last_paused`; cleared at the next
  launch of that run. `RunCommand._exit_if_paused` turns it into **exit code
  3** with a resume hint. The supervisor itself never sleeps.

## 6. Phase F — HyperGraph

### 6.1 The adapter (`blueprint/hgraph_graph.py`)
`build_project_graph(project_root, blueprint_dir, sync=True)`:

1. Blueprint entry: `<project>/hgraph/config.yaml` (`hgraph.sync.load_config`)
   wins; else auto-detect `web|print|content.tex` under `blueprint(/src)`.
   Lean paths: config, else the whole project root.
2. `Graph.open(project)` + `hgraph.sync.sync(...)` — idempotent; **writes**
   `<project>/hgraph/` (nodes/edges as Markdown files). Authored fields
   (comments, reviews, manual metadata) are never touched by sync.
3. Serialisation into Horizon's shape:
   - nodes = tex nodes **with a `label`** only (unlabeled quotes/proof bodies
     are hgraph-internal), keyed by that label, ordered by (chapter, order);
   - **edge inversion**: hgraph stores dependent→dependency; Horizon emits
     dependency→dependent (`{"source": label(e.target), "target": label(e.source)}`);
   - `formalizes` edges (handled in either direction) fold the Lean nodes into
     `lean_name` / `lean_source` / `lean_file` / `has_sorry`;
   - status: `proved` ⇔ `lean_status ∈ {lean_ok, mathlib_ok}` — **derived from
     scanning the Lean, `\leanok` is not trusted**;
   - extra per-node keys the old engines didn't have: `state`
     (closed/ready/blocked/formalized_open from `Analysis`), `unlocks`
     (downstream impact), `comment_count`/`review_count` (attachment files),
     `hgraph_id` (for CLI addressing without a label lookup);
   - `dangling` parsed from sync warnings (`\uses{X} has no blueprint node`);
   - `meta = {engine: "hgraph", entry, macros, states, warnings[:50]}` — macros
     come from Horizon's own `chapters.parse_macros` over the blueprint `.tex`.
4. Any hgraph exception ⇒ `return None` ⇒ fallback.

Resolution order in `blueprint/workspace.py project_rich_dag`:
**hgraph → vendored leandag → parser DAG**. The orchestrator's "never downgrade
a rich cache" guard accepts `engine ∈ {leandag, hgraph}`.

**⚠ decision:** hgraph is now a **default dependency**
(`pyproject.toml dependencies`, git URL `AxelDlv00/hgraph`) rather than an
extra — per your request. The import is still guarded so a broken/absent
install degrades instead of crashing. Locally the venv has it **editable from
`/home/axel/HyperGraph`**, so your local hgraph edits take effect immediately.
**⚠ decision:** vendored `leandag/` is *kept* as the fallback (the plan said
delete; removing it is a follow-up once hgraph is everywhere).
**⚠ side effect to be aware of:** the first publish boundary on an existing
workspace (e.g. OpenGA-Horizon) will create `<project>/hgraph/` file trees and
they will be committed to the ledger by the normal session integration. That
is the intended adoption path, but it is a visible diff.

### 6.2 Frontend (`frontend/src/BlueprintPage.tsx`, `App.tsx`, `api.ts`)
- `Squares` / `SegBar` / `StatusLegend`: 12 px flex cells + proportional bar,
  colored by hgraph's palette (`STATUS_COLOR`: mathlib `#0B5FD0`, leanok
  `#137333`, sorry `#C2410C`, todo `#6B7280`). Shown on the Blueprint
  table-of-contents landing view: one squares row per chapter (statement-level,
  remark-likes skipped), each square clickable to its statement; an overall
  segbar + legend on top. A new `sorry` status is derived from the DAG node's
  `has_sorry`/`lean_status`.
- `/api/blueprints` (new registry endpoint) carries the light DAGs;
  `state()` no longer does. `App.tsx reload()` fetches both in parallel and
  merges (`{...state, blueprints}`), so every downstream consumer of
  `state.blueprints` is unchanged; the per-URL ETag cache makes the blueprints

  automatically (it exports whatever `endpoints()` lists).
- `dist/` is gitignored as before — I built it locally (`npm run build`);
  rebuild after pulling.

## 9. Follow-up batch — "no legacy left" (same branch, after review feedback)

All the ⚠ conservative keeps above were resolved in favor of deletion, plus new
operational surface:

- **Vendored `leandag/` deleted** (with `blueprint/leandag_graph.py`). Rich DAG
  resolution is now `hgraph → parser`; the cached-engine downgrade guard still
  accepts old `engine: "leandag"` caches. `horizon leandag` (CLI) is unchanged —
  it queries the cached DAG JSON, not the engine.
- **`ground_agent` config concept fully removed** (schema, init template,
  interactive prompts, `_ROLE_AUTHORS`, author-role sets). `discuss`, the
  post-init advisor, and `horizon subagent` use the horizon harness. Old
  `ground_agent:` keys in a config are ignored.
- **The aggregate "Changes" view is gone** (`/api/run/changes`,
  `/api/run/working-changes`, `run_changes`/`working_changes`,
  `aggregate_session_summary`, the worktree diff path, `run_agent_changed_files`,
  and the `SessionChanges` panel + helpers in App.tsx). The commit cards
  (`/api/session/commits` + per-commit `&sha=` file diffs) are the one change
  view, rendered for every selected session.
- **Session identity via env** (`agents/harness_agents._agent_env`): adds
  `ARCHON_HORIZON_SESSION_DIR`, `ARCHON_HORIZON_ROUND`, `ARCHON_HORIZON_ROUNDS`,
  `ARCHON_HORIZON_TASK_TITLE` to the existing ROOT/RUN/SESSION/TASK/PROJECTS.
  The task itself still arrives as the prompt directive (a session needs its
  goal in-band); the env carries identity for CLI calls and pacing. The env
  table is documented in the `horizon` skill.
- **Process registry**: the orchestrator writes `runs/<id>/process.json`
  (pid/host/started_at) for the duration of a run; `horizon ps` lists live
  runs, flags `zombie-marker` (pid dead) and `stalled` (alive, no run-dir
  writes for 30 min), `--clean` reaps dead markers, `--kill <run>` SIGTERM→
  SIGKILLs a local stuck run. State on disk is never touched; `--resume`
  continues a killed run. This is also the groundwork for parallel-run
  awareness (a second `horizon run` can see who else is live).
- **Usage guidance reframed** (horizon + subagents skills): not "avoid
  launching agents" but "make interruption cheap" — commit at every coherent
  point, commit NOW when headroom is low or limit signals appear, and leave the
  workspace hand-off-clean on the run's last round (`ARCHON_HORIZON_ROUND`).
- **Remaining prompts trimmed to skill-first**: the post-init advisor and
  `discuss` seeds now load the horizon skill and keep only their
  rules-of-engagement; the old orientation/role-brief prose is gone.
- `uv.lock` includes hgraph; the frontend `dist` rebuild is required after
  pulling (`npm run build` — dist is gitignored).
